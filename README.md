# RiskLedger

A dark-mode ISO/IEC 27001 risk register, risk matrix, and Statement of Applicability (SOA) tool — built as a single client-side web app with no backend and no build step. Multiple organizations can sign up and manage their own risks, admins, and compliance tracking independently in the same app.

An AI advisor (powered by the Google Gemini API) suggests relevant ISO/IEC 27001:2022 Annex A controls for each risk you log.

## Features

- **Multi-organization sign-up / sign-in** — each organization's admins, risks, and SOA data are kept separate.
- **Role-based access** — every organization has one **Head Admin** (the creator) who can add, remove, and reset passwords for other admins. Regular admins can use the app but can't manage the team.
- **Password recovery** — the head admin sets a security question at sign-up for self-service password reset. Other admins get their password reset by the head admin from the Team tab.
- **Risk register (ledger)** — log risks with asset, category, threat, vulnerability, existing controls, likelihood/impact (auto-scored 1–25), owner, status, and treatment plan. Search and filter by status.
- **Risk matrix** — a 5×5 likelihood × impact heatmap, color-banded Low / Medium / High / Critical. Click a cell to filter the register to that bucket.
- **AI advisor** — for any risk, request 2–4 relevant ISO/IEC 27001:2022 Annex A controls with a short rationale for each, generated by the Gemini API.
- **Statement of Applicability (SOA)** — the full 93-control Annex A:2022 list, grouped by theme (Organizational, People, Physical, Technological). Mark each control Applicable / Not applicable, set an implementation status, write a justification, and see which logged risks reference it. Export the whole SOA as a CSV, or use "Print / Save PDF" for a clean printable version.
- **Dark theme** throughout.

## Tech stack

Plain HTML, CSS, and JavaScript — no framework, no npm install, no build step. Data is stored in the browser's `localStorage`. The only network call the app makes is to the Gemini API when you use the AI advisor.

```
risk-ledger/
├── index.html      # page shell
├── css/
│   └── styles.css   # all styling
└── js/
    └── app.js        # all application logic
```

## Getting started

1. Clone or download this repository.
2. Open the `risk-ledger` folder in VS Code (or any editor).
3. Open `index.html` with the **Live Server** extension (or any static file server — see note below).
4. Sign up to create your organization and head admin account.

> **Note:** opening `index.html` by double-clicking it usually works too, but a local server (Live Server, `python -m http.server`, etc.) is more reliable and avoids browser quirks with `file://` paths.

### Connecting the AI advisor (Gemini API)

1. Get a free API key from [Google AI Studio](https://aistudio.google.com/apikey) — no credit card required.
2. In the app, go to **Settings** in the sidebar.
3. Paste your key into the **Gemini API key** field and click **Save key**.
4. Open any risk's detail view and click **Get recommendation**.

The app currently calls `gemini-3.6-flash`, a Gemini free-tier model as of writing. If Google retires or renames this model, update the `GEMINI_MODEL` constant near the top of `runAiAdvisor()` in `js/app.js` — check [ai.google.dev/gemini-api/docs/pricing](https://ai.google.dev/gemini-api/docs/pricing) for the current free-tier model list.

## ⚠️ Security notes — read before deploying anywhere public

This project was built for **local, personal, or small-team use** and deliberately has no backend. That comes with real limitations you should not carry into a production or public deployment:

- **Passwords are stored in plain text** in the browser's `localStorage`. There is no hashing, no salting, and no real authentication server. Do not reuse a real password for this app.
- **The Gemini API key is stored in `localStorage` and used directly from the browser.** It is visible to anyone who opens DevTools → Network/Application tabs on that browser. Each person running the app locally should use their own free key — never hardcode a shared key into the source and never deploy this as-is to a public URL.
- **`localStorage` is per-browser, per-device.** Data does not sync across devices or browsers, and clearing browser storage deletes everything. There's no backup beyond the CSV export on the SOA page.
- If you want to turn this into something you can safely share or deploy publicly, the AI advisor call needs to move behind a real backend that holds the API key server-side, and authentication needs a real hashing/session system with a proper database.
